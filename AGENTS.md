# Jev for Homey

Build a Homey SDK v3 app for TypeSafe Jev decisions. The app targets local Homey devices running Homey 12.4 or newer. Use Bun for dependency installation, scripts and tests. The runtime is Node 22.

## Product rules

- The user supplies all context as text and Homey Flow tags on each evaluation. A decision may also contain optional, user-written background information.
- Never discover devices, collect sensor states, build a house snapshot or add automatic context gathering. This is a deliberate product decision, including for future features.
- A decision has a stable ID, name, question, type, thresholds and validity settings. Choice options have stable IDs separate from names. Renaming must not break Flows.
- Version 0.1 supports Choice and Noul. Score, batching and caching are future work, not existing functionality.
- Jev makes typed judgments; it does not generate explanations, chat responses or device commands. Homey Flows execute actions.
- A Noul value is the probability of yes. It is not a separate confidence measure. Choice returns both probabilities and confidence.
- Uncertainty, API failure, expiry, cooldown and superseded requests must never turn into a valid no answer.
- Test evaluations call the paid API but never update accepted state or trigger Flows.
- Never store supplied per-call context in history or log API keys, request bodies or provider error bodies. History is limited to 50 entries.

## Layout

- `src/brain/jev.ts`: the TypeSafe HTTP boundary and runtime response validation.
- `src/brain/decisions.ts`: persistence-independent decision engine, concurrency, thresholds, validity and history.
- `src/validation.ts`: validation for every settings/API mutation.
- `src/flow/index.ts`: Homey card registration, autocomplete and tokens.
- `src/index.ts`: Homey app lifecycle and adapters for settings and triggers.
- `api.ts`: settings endpoints. Never expose the stored API key on reads.
- `.homeycompose/app.json` and `.homeycompose/flow/`: source manifests. Root `app.json` is generated by Homey; do not edit it manually.
- `settings-ui/`: Vue 3 with TypeScript, components and a feature composable. Builds to `settings/`.
- `tests/`: Bun tests with mocked HTTP and a controlled clock. No live credentials are needed.

## Commands

```sh
bun install
bun install --cwd settings-ui
bun run typecheck
bun test
bun run build
homey app build
```

Run both the app build and Homey validation before declaring a change ready. `homey app build` does not build the Vue UI; run `bun run build` first. Use `homey app run` only when the user wants installation on a Homey. Never publish a release or change repository visibility without a request.

## Conventions

Use the existing `@basmilius/homey-common` base App and native Homey Flow API. Keep decision logic independent of Homey so it can be tested with injected dependencies. Use type aliases, explicit types, four-space indentation and concise comments explaining constraints rather than narrating code.

Vue components use template, script setup, style order. The view coordinates components through `useJev`; components emit events instead of fetching data. Shared iframe styles live in `style.css`; component-only styles use CSS modules. User-facing UI and card text ship in English and Dutch.

Treat settings input and TypeSafe responses as untrusted. Validate bounds, option membership and probability distributions. Settings changes and decision edits invalidate results and pending evaluations. The newest production request wins. Keep each Advanced Flow result local to its invocation.

Only accepted evaluations return action tokens. Other statuses reject the action so Advanced Flow takes its error path. Regular Flows use `unavailable` for these statuses. `outcome_is` throws if no current accepted result exists, including when the card is inverted.

## Sources and access

Official API reference: https://docs.typesafe.ai/api
Choice: https://docs.typesafe.ai/primitives/choice
Noul: https://docs.typesafe.ai/primitives/noul

Use `POST https://api.typesafe.ai/v1/systemone` with a bearer key. Model defaults to `jev-latest`; users can pin a supported version. There are no automatic retries because evaluations consume credit. Verify API changes against official docs before editing the contract.

GitHub repository: https://github.com/basmilius/homey-jev. Keep it private. Claude and FlowBits are sibling repositories for reference, not dependencies to modify.

Settings UI must match the sibling Claude app and Homey's native settings UI. Reuse the `Top`, `Form`, `FormGroup`, input and button components with `homey-*` classes. Let Homey supply theme, typography and control styles through `/homey.js`; keep custom CSS limited to layout. Do not add a separate branded theme or card-based dashboard.
